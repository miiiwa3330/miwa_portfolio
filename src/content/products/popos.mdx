## 電波もサーバーも使わず、全員の端末が対等なレジになる

popos（`popos.miiiwa.com`）は、屋外の露店やポップアップ出店など、電波が届きにくい場所でも複数人がそれぞれのスマートフォンやタブレットで会計を行える、完全オフライン動作の POS レジ PWA です。何人かで商品を持ち寄って1つの店を出す場面を想定し、機材購入費や月額費用、Wi-Fi ルーターを一切必要としない構成で設計しています。

一般的なクラウド型 POS アプリとは異なり、バックエンドのデータベースを持たず、サーバーの役割は Cloudflare Pages からアプリの静的ファイルを配信するだけに限定しました。iPhone・iPad の Safari からホーム画面に追加して初回に1度だけ起動すれば、QR コード読み取り用の WebAssembly（`zxing-wasm`）を含めた全アセットが端末内にキャッシュされ、その後は完全にインターネット圏外であってもレジ打ち・在庫確認・集計・端末間同期のすべてが動作します。

各端末は完全に**対等（ピアツーピア）**であり、親子関係や専用親機のような単一障害点を持ちません。1人が自分の端末でイベントを作成し、他のメンバーは「イベントに入る」から QR コードを読み取るだけで商品一覧・在庫・メンバー情報を受け取って即座に同じ売場のレジに参加できます。売上記録は各端末の IndexedDB に保持されるため、インターネット回線が不安定な環境でも待ち時間ゼロで確定処理が進み、万が一1台の端末が壊れたり電池切れになったりしても、他のメンバーの端末やバックアップファイルから記録を復元できます。

## イベント単位の管理と、持ち主ごとの集計・税計算

データ構造の最上位には、カレンダーに並ぶ**開催（イベント）**を置いています。同じメンバーで何度も出店する運用に合わせ、イベントごとに店舗設定・税の端数処理・メンバー・持ち主・商品・在庫・会計ログを完全に分離して保持します。

- **テンプレート複製と在庫引き継ぎ**: 新しいイベントを作成する際は、過去のイベントを選んで商品名・単価・税区分・持ち主の並びをそのまま複製できます。初期在庫は「前回の残り」か「0から」を選択でき、開始前に個別の数量を − / ＋ で微調整してから営業を始められます
- **持ち主ごとの色分けと集計**: 複数の出品者で売場を共有するケースに対応し、12色のタグで持ち主を色分けできます。レジ画面では持ち主ごとの絞り込みができ、売上タブからは持ち主別・商品別の税込売上・税抜金額・税額・販売点数・残数を一覧で確認できます
- **誤差を出さない金額・税計算と追記型ログ**: 金額はすべて円の整数で扱い、税率も浮動小数点を使わず `0.01%` を `1` とする整数（`0〜100%`、小数第2位まで）で管理しています。商品ごとに税込／税抜と税率を個別に設定し、イベント単位で端数処理（切り捨て・四捨五入・切り上げ）を選べます。確定した会計ログは上書きせず、取り消しも「打ち消し記録（`sale.voided`）」を追記して履歴を残す仕組みです
- **CSV 書き出しと全イベントバックアップ**: 売上画面から会計明細および持ち主別集計の CSV ファイルを書き出して OS の共有シートや「ファイル」アプリへ保存できるほか、端末内の全開催を1ファイルにまとめたバックアップの保存・復元にも対応しています

## 暗号化した分割 QR コードによる端末間同期

Web ブラウザ上でサーバーを介さずに複数端末を同期させるにあたり、通信手段の選定では現実のブラウザ制約を検証したうえで QR コード方式を採用しました。iPhone・iPad の Safari は Web Bluetooth に対応しておらず、対応する Android や PC の Chrome でも Web Bluetooth は接続しに行く側（セントラル）にしかなれないため、ブラウザ同士の直接接続が成立しません。そこで、カメラと画面さえあれば OS を問わず確実にやりとりできる**分割アニメーション QR コードによる往復同期**を実装しました。

同期の中身は、端末ごとに発番した「起きたことの追記ログ（`端末ID.通し番号`）」と、どの端末の何番までを隙間なく保持しているかを示すベクタークロック（`vector`）です。

- **圧縮・暗号化・順不同フレーム分割**: 送信時はイベントごとの記録と `vector` を JSON 化し、ブラウザ標準の `CompressionStream`（`deflate-raw`）で圧縮したうえで、Web Crypto API の `AES-GCM` とイベント固有鍵で暗号化します。1フレーム 900 バイト単位に分割し、250 ミリ秒間隔で自動切替表示するアニメーション QR として出力します。読み取り側はカメラを向けたまま待つだけで、どの順序でフレームを拾ってもハッシュ検証付きで元データを復元します
- **「QR を読む / QR を出す」の迷わない動線**: 1対1の交換も全員分のホスト集約も共通の2手順に統一しました。「QR を読む」から相手の QR を1人または複数人続けて読み取ると、各人の `vector` の最小公倍数的な下限をもとにまだ相手が持っていない差分記録だけをまとめた返し・配布用 QR を自動生成します
- **そろい番号と Git のような未送信バッジ**: 全員の記録が一致しているかをひと目で確かめられるよう、全端末の `vector` から計算する4桁の数字＋8色の「**そろい番号**」を大きく表示します。さらに各メンバー行の右には、Git の ahead に相当する「自分の端末から相手にまだ渡していない記録の件数」を赤いバッジで表示し、やりとりの抜け漏れを防ぎます
- **編集衝突（食い違い）の検出と解消**: オフライン環境では同じ商品や持ち主を別々の端末で編集する競合が起こり得ます。編集元バージョン（`base`）を記録することで分岐を自動検出し、食い違いが生じた項目には両方の変更内容と変更者・時刻を並べて「残すほう」を選べる解決 UI を用意しました

## 誰でも迷わず操作できる UI とアクセシビリティ設計

スマホやタブレット操作に不慣れな人や高齢の出店者でも実戦の露店で迷わず使えるよう、UI は iOS 標準アプリを基準とした高い視認性と操作安全性を最優先に組んでいます。

- **3段階の文字サイズと明確なコントラスト**: 設定からページ全体の文字基準を「標準（18px）・大（20px）・特大（24px）」で切り替えられ（初期値は「大」）、文字拡大に合わせてボタンや余白も連動します。5項目の下部タブバーは折り返しを防ぐため 14px に抑えつつ、色だけに頼らない表示（たとえば在庫 `0` 以下でも販売は止めず「在庫なし」の赤文字と色表示の両方で知らせる）を徹底しました
- **会計確定の誤操作防止と全角入力の吸収**: レジ画面はタブレット・PC の広い横幅では左に商品タイル・右にかごとお会計を並べた2カラム、スマートフォンでは下部バーからかごを開く構成とし、金額入力時はテンキーと主要紙幣ボタン（ちょうど・1,000・5,000・10,000円）を用意して、最後に合計とお預かり・お釣りを大きく確認してから確定できます。数値入力欄では日本語入力由来の全角数字や小数点も自動で半角へ正規化します
- **PWA のカメラ許可維持とデータ保護**: iOS のホーム画面アプリでは画面切り替えで URL が遷移するとカメラ許可を毎回聞き直される既知の問題を避けるため、URL を変えずに状態だけでタブとモーダルを切り替えます。また、`navigator.storage.persist()` によるストレージ永続化の要求や、7日削除ルールのある Safari タブではなくホーム画面アイコンからの利用を案内する設計を取り入れました

## 技術構成とオフライン永続化

クライアントは React 19、Vite 8、TypeScript 7、Tailwind CSS 4 で構築し、`vite-plugin-pwa` 2 によって静的アセットおよび `zxing-wasm` の WASM バイナリを Service Worker でプリキャッシュしています。データ永続化には Dexie 4（IndexedDB）を用い、記録ログ・イベントメタ情報・端末設定の3テーブルをトランザクション単位で整合性を保ちながら書き込みます。

QR コードの生成には `qrcode`、読み取りには `zxing-wasm`（および対応ブラウザでの標準 `BarcodeDetector`）を使用し、圧縮・暗号化は追加ライブラリを使わずにブラウザ標準 API（`CompressionStream` / Web Crypto API）のみで完結させました。金額・税・同期アルゴリズム・データ移行のコアロジックは UI から完全に切り離して Vitest 5 で単体テストし、カメラ動画をモックした一連のレジ・同期フローを Playwright で E2E 検証したうえで Cloudflare Pages（`popos.miiiwa.com`）へデプロイしています。
