# 見た目の確認と計測の手順

ヘッドレス Chrome でこのサイトを撮る方法と、**測ってはいけない測り方**。ここを守らないと「存在しない差を測って、間違った値に合わせ込む」ことになる。

`curl` や一発の `chrome --screenshot` では**白いキャンバスしか撮れない**（WebGL の描画前に走るため。`--virtual-time-budget` は R3F の rAF ループのせいで永久にハングする）。スクラッチパッドに `puppeteer-core` を入れ、以下で撮る。

- `executablePath` に `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`、`headless: "new"`
- 起動引数 `--no-sandbox --enable-unsafe-swiftshader --use-gl=angle --use-angle=swiftshader`（ヘッドレスに GPU がないのでソフトウェア WebGL）
- `waitUntil: "networkidle2"` の後、描画されるまで **7秒ほど待ってから** `page.screenshot`
- `console` / `pageerror` を拾ってランタイムエラーを検出する
- 開発サーバーのスクショ左下に出る黒丸は Next.js の dev インジケーターであって、アプリの UI ではない

**ヘッドレスで「滑らかさ」は測れない。** SwiftShader はソフトウェアラスタライズなので、このシーンは**毎秒3フレーム程度**しか出ない（実測: 3秒間で4フレーム、間隔 333〜1233ms）。rAF の間隔を取ってもフレーム落ちの診断にはならず、時間で進むアニメーションは実時間で何倍にも伸びる。見た目の確認と状態の確認には使えるので、**動きの質はコード側の算術とテストで固め、体感は実機に回す。**

**カメラの飛行が絡む操作は、単純な「秒数×倍率」よりさらに待つ。** `MAX_FLIGHT_STEP`（`Scene.tsx`）が1フレームあたりの進行を0.1秒に固定でクランプするため、1.1秒の飛行は実時間の長さに関わらず最低11フレームを要る——毎秒3フレーム、間隔が1秒を超えるフレームもある実測を踏まえると、8秒待っても着地しきっていないことがある（着地前に撮ると、距離が変わる操作なのに「ほとんど動いていないように見える」という誤った結論を導く）。1回の待機時間を勘で決めず、**数秒おきに複数枚撮って値が収束したかを見る**のが確実。

**`page.mouse.wheel` は使わない。** CDP 経由で1回あたり3〜5秒かかり、実用にならない（About の長いスクロールで実測）。`window.dispatchEvent(new WheelEvent("wheel", { deltaY }))` を、対象の要素上で（`document.elementFromPoint(x, y)` から）まとめて投げるほうが速く確実——1回の `page.evaluate` の中で数十発ディスパッチしても即座に終わる。ホイールで進む量は `WHEEL_SENSITIVITY` から逆算できる。

**マウスドラッグも間隔を詰めない。** `steps` を大きくして待機を200〜300msまで詰めると、Chrome のタブが `Target closed` で本当に落ちることがある（惑星＋雑居ビル＋装飾一式でシーンが重くなってから顕著）。`steps=5` 程度・待機800ms以上に緩め、スクリプトが途中で落ちたらゾンビ化した Chrome プロセスを `pkill` してから次を走らせる。動きそのものを検証したいのでなければ、間隔を詰める理由はそもそも無い。

マーカーの画面座標などをヘッドレスで測って使うときは、**測定とクリックを同じスクリプト実行の中で行う。** アイドル回転がページ読み込みからの経過時間ぶん常に進んでいるため、別のスクリプト実行で測った座標を使い回すと、測った瞬間と実際にクリックする瞬間のずれでマーカーが動いてしまう。

構図をピクセルで測るときは、次の2つを守る。どちらも守らないと**存在しない差を測って、間違った値に合わせ込む**ことになる。

- **星屑や紙吹雪のような漂うオブジェクトを除外する。** 「背景色と違う画素の min/max」で島や惑星の幅を測ると、画面の隅まで漂うそれらが端を決めてしまう（旧・平面の島での実測でフレーム幅83%と出たが、本当の島は57%だった）。列ごとに画素数を数え、**フレーム高さの1割**を超える列だけを採用する。2% では縦の重なりが通ってしまう
- **一周ぶんサンプリングして最悪角度で判断する。** 回るとシルエットが伸縮する形をしているため、少ない角度数では見落とす（旧・平面の島で、5角度では右端を94.6%と報告した設定が、16角度に増やすと98%台の角度を複数出した）

## スマホを測るときに追加で踏む罠

**`page.touchscreen.tap()` は down→up に数秒かかる。** SwiftShader 下の実測で **4083ms**（CDP の往復が遅い。`page.mouse.wheel` と同じ理由）。タップかどうかを時間で判定している実装（`useTapGesture` の 350ms）は、これでは**必ず不成立になる**。「タップが効かない」という誤った結論をここで1回出した。1回の `page.evaluate` の中で `pointerdown`／`pointerup` を自分で `dispatchEvent` すれば、実機並みの間隔（同一タスク内）で投げられる。

**合成した `PointerEvent` は R3F のレイキャストに届かない。** R3F はポインタ位置を `offsetX`/`offsetY` から取るが、`PointerEvent` のコンストラクタは `clientX`/`clientY` しか受け付けず、`offsetX` は **0 のまま**になる。結果として**常にキャンバスの左上を撃つ**ので、狙ったマーカーではなく「たまたま左上にあったもの」が反応する（これで「マーカーをタップすると停止もしてしまう」という存在しない不具合を1回報告しかけた）。生成後に `Object.defineProperty(e, "offsetX", { get: () => x - rect.left })` を生やしてから投げる。

**PC のトラックパッドのピンチは `ctrlKey: true` の `WheelEvent` で再現する。** `PointerEvent` を2つ投げる形では**実機スマホの経路しか通らない**。逆にスマホの2本指は `PointerEvent`（`pointerId` 違い）でしか再現できない。**どちらのジェスチャも、両方の投げ方で確かめる**こと——片方だけで「実装した」と結論すると、もう片方の環境で無反応のまま出荷される（実際に1回そうなった）。

**ジェスチャがカメラを動かしたかどうかは、停止してから前後の画素を比べる。** アイドル回転が常に進んでいるので「変わった＝効いた」にはならない。空タップ（スマホ）か停止ボタン（PC）で止めてから、**何もしない対照**を1枚挟む——止まっていれば対照の差分は 0.0% になるので、そのあとの差分はジェスチャぶんだと言い切れる。

**マーカーは点線の末端にはいない。** 点線は `markerClearance()` のぶん手前で切られているので、末端の座標をそのままタップしても外れる。末端の1つ手前の点との差を方向ベクトルにして、数十px 先まで順に叩いて探すのが確実。

**「一周ぶんサンプリング」は開始点を揃えるところまで含む。** アイドル回転が進んだ任意の位置から20点取ると、同じ設定でも**実行ごとに違う弧**を測ることになり、候補値の優劣が逆転する（縦オフセットの比較で 0.20 が 0.15 より良くも悪くも出た）。ロゴのクリック＝ツアーの u=0 へのリセットを共通の開始点にしてから測る。1サンプルあたりのホイール量は `ツアー全長 / サンプル数 / WHEEL_SENSITIVITY`（全長は 6.326 rad）。

**スマホの構図は「占有率」だけでは語れない。** `near` では惑星は円盤ではなく画面いっぱいの風景なので、「何%を覆っているか」はどの設定でも 65〜94% の間にしかならず、差が読めない。**空と地面の境界の y**（幅の半分以上が背景色でなくなる最初の行）を測ると、設定に対して線形に動くので比較できる。

**Next.js の開発インジケーターがヘッダーのボタンを覆う。** 390px 幅で `#devtools-indicator` は [334,20,36,36] に出て、ヘッダー右端のボタン [318,28,44,44] に重なる——`document.elementFromPoint` がボタンではなく `NEXTJS-PORTAL` を返し、**実際に押せなくなる**。`devIndicators: { position: ... }` では動かせなかった（スキーマは4つの位置を受け付け既定値も 'bottom-left' なのに、描画は右上のまま。Next 16.2.10）。`next.config.ts` で `devIndicators: false` にしてある。本番ビルドには存在しないので、**この不具合を「サイトの不具合」と誤診しない**。

**`next.config.ts` の変更は HMR では効かない。** dev サーバーを落として起動し直す必要がある。さらに `pkill -f "next dev"` では死に残ることがあり、ポート3000を掴んだままの旧プロセスに新しいプロセスが接続して「設定を変えたのに変わらない」状態になる。`lsof -ti:3000 -sTCP:LISTEN | xargs kill -9` で確実に落としてから起動する。

**`-sTCP:LISTEN` を省かない。** `lsof -ti:3000` は待ち受けているサーバーだけでなく、**ポート3000へ接続している側**も返す。localhost:3000 のタブを開いたままのブラウザがあると、その **Chrome のネットワークプロセス**（`Google Chrome Helper --utility-sub-type=network.mojom.NetworkService`）まで `kill -9` の対象になる（2026-09-18 に実際に巻き込んだ。Chrome は自動で立て直すが、開いていたタブの通信は切れる）。自分で起動したサーバーを止めるだけなら、起動時の PID を控えて `kill <PID>` するのが一番確実。

**バックグラウンドで起動したサーバーの PID は、サブシェルで包まずに取る。** `( python3 -m http.server 8765 & echo $! > server.pid )` の `$!` はサブシェル側の PID になることがあり、`kill $(cat server.pid)` が成功したように見えても `http.server` 本体が残った（2026-10-01、次の起動で `kill` が `no such process` になって気づいた）。`python3 -m http.server 8765 & SERVER=$!` と同じシェルで取り、止めたあとに `lsof -ti:8765 -sTCP:LISTEN` で空いたことを確かめる

**`page.setViewport` で `isMobile`/`hasTouch` を切り替えるとページが再読み込みされる。** アプリの状態（`activeSection` など）が全部リセットされるので、「PC 幅で状態を作ってスマホ幅で確認する」という手は使えない。状態を作る操作はスマホ幅のまま行う。

**AnimatePresence の退場はヘッドレスでは実時間で何倍にもなる。** `exit` が 0.14 秒でも、毎秒3フレームでは DOM から消えるまで1秒以上かかる。「閉じるボタンが効かない」と誤診しかけた（600ms 後に確認して残っていた／1.6秒後には消えていた）。

## 読み物のページを確かめるとき（2026-09-19）

**`out/` の配信は `.html` を補うサーバーで行う。** 本番（Vercel）は `/products/imadoko` に `products/imadoko.html` を返すが、`python3 -m http.server` はそれをしない（404）。スクラッチパッドに「パスが無ければ `.html` を足して探す」だけの `SimpleHTTPRequestHandler` を書いて配信した。**同名のディレクトリがあるときも `.html` を優先する。** `out/` には `notes.html` と `notes/`（個別ページの置き場）が並ぶので、「パスが無ければ」の条件だと `/notes` はディレクトリとして見つかり、`/notes/` への 301 になる（2026-09-20）。末尾が `/` でないパスは、`.html` があればそちらを返す

**トップを開くときは広告の通信を遮断する。** `layout.tsx` の AdSense のスクリプトが外部へ通信し続けるので、`waitUntil: "networkidle2"` が30秒でタイムアウトした。`page.setRequestInterception(true)` で `googlesyndication` への要求を `abort()` し、`waitUntil: "domcontentloaded"` ＋固定の待ちにした。遮断した要求はコンソールに `net::ERR_FAILED` として1件出るが、アプリのエラーではない。読み物のページ（WebGL 無し）は `networkidle0` で問題なく開ける。

**幅のしきい値を測るときは、同じページで要素を消した状態とも比べる。** ヘッダーのナビに1項目足したら折り返したが、それが足したせいなのか元からなのかは、足した要素を `display: none` にして同じ幅で測り直すと切り分けられる（元の版をビルドし直す必要が無い）。実際、1024〜1100px の2行の折り返しは元からで、1200px の折り返しと 1024px の3行が足したぶんだった。

**ユーザーの `next dev` が動いているかもしれない。** ビルドの前に `.next` を消そうとしたら、`.next/dev/cache/turbopack` に書き込みが続いていて消しきれなかった——ポート3000で `next dev` が動いていた。**確認せずに `.next` を消さない**（開発サーバーのキャッシュを壊しうる）。`next build` が一度 `.next/server` の削除で `ENOTEMPTY` になった。そのあと `rm -rf .next` を試し（上のとおり途中で止まった）、もう一度 `next build` を走らせたら通った——どちらが効いたのかは切り分けていない。

**「文字が2行に折れていないか」はテキストノードの矩形だけで数える。** リンクやボタン全体を `Range` で囲んで `getClientRects()` の上端を数えると、アイコンの SVG の上端が別の行として数えられ、1行に収まっているアイコン付きのボタンが全部「2行」になる（2026-09-19 に読み物の95ページ幅のうち73で誤検出）。`TreeWalker` でテキストノードだけを歩いて上端を集める。**直した検出器が「見つけられる」ことも確かめる**——何も見つけないのが直ったからなのか見えなくなったからなのかは、結果が0件では区別できない。対象の1つを `white-space: normal; width: 60px` にして折り返させ、検出されることを見た（1行 → 3行）

**読み物のページからハブへの遷移を確かめるときは、着いた先のシートが開いたかまで見る。** URL が `/#experience` になったことだけでは足りない——`next/link` で移ったときは URL が変わってもシートは開いていなかった（`AppStateProvider` がページをまたいで生き残るため。[tech.md](tech.md) の「読み物のページ」）。素の `<a>` なら普通の遷移なので、`page.waitForNavigation()` と一緒にクリックし、WebGL の初期化を待ってから（数秒）シートの見出しを読む

**`npm run build` が `ENOTEMPTY: directory not empty, rmdir '.next/server'` で落ちることがある。** 2026-09-19 に1回。直後の `.next/server` は空で、`lsof` で掴んでいるプロセスも無く、そのまま再実行して通った。`.next` ごと消して直そうとしない——ユーザーの `next dev` が `.next/dev` を使って動いていることがある（2026-09-19 の devlog の「踏んだ罠」）。2026-09-20 にも1回。**直後の `.next/server` には `.DS_Store`（Finder が作るファイル）が1つだけ残っていた**——削除の途中で Finder が作り直した可能性がある（未検証）。このときも再実行で通った

**カードの見出しを `document.querySelector("h3")` で読まない。** 先に見つかるのは `hub/SemanticSEO.tsx` の画面に出ない見出しで、どの状態でも同じ文字（制作実績の1件目の名前）が返る（2026-10-01、ホイールで回しても「変わらない」と読み違えかけた）。画面の状態は撮った画像で判断するか、`.sr-only` の外の要素に絞る

**「画面に見える文字」を `document.body.innerText` で数えない。** `sr-only` は `clip` で見えなくしているだけで `display: none` ではないので、`innerText` に入る。2026-09-20 に本番トップを測ったら3,407字と出たが、約3,300字は `hub/SemanticSEO.tsx` の画面に出ない文章だった。見えるリンクや文字を数えるときは、要素ごとに `el.closest(".sr-only")` で除き、`getBoundingClientRect()` の幅と高さが0でないものだけを取る（この方法で、トップの初期表示に見えるリンクは PC で `/privacy` の1本、スマホで0本と出た）
