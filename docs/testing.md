# テスト方針

Vitest（node 環境）で、**React も three.js も含まない純粋ロジックだけ**をテストする。DOM もレンダラも要らないので全体が高速に回る。対象は部屋の配置・カメラの姿勢と飛行・レンズの式・CSS の3D変換・体の関節・決定論的ハッシュ・実績フィルタ・言語解決・URL 解釈など（一覧は [tech.md](tech.md) の「テスト」）。

下の教訓には、惑星の頃のテスト（`cameraLayout.test.ts`・`sunLight.test.ts` など。2026-10-01 に部屋への移行で外した）の例が出てくる。ファイルは無くなったが、教訓は部屋でもそのまま効く。部屋の移行で得た教訓は最後の3つ。

新しいテストは**変異テストで検証してから完了とする**。わざとバグを仕込んで落ちることを確認していないテストは、緑でも意味がない。

- **変異を戻すのに `git checkout <file>` を使わない。** 未コミットの変更ごと消える（実際に消した）。`cp` でスクラッチパッドへ退避してから当て、`cp` で戻す
- **定数を自分自身と比べるテストは何も言っていない。** `shouldReturnHome(ABOUT_RETURN_AT, ...)` はしきい値を 1 にしても緑のままだった。閾値まわりはリテラルで書く。2026-10-22 にも同じ形を踏んだ: キーの角が丸いことを「足の角から `CAP.footRadius × (√2 − 1)` 以上離れている」で確かめたら、丸みをほぼ0にする変異でしきい値も一緒に縮んで緑だった。写真から決めた下限（0.3mm）のリテラルにして落ちるようになった
- **テストが通す入力が現実の経路かを確かめる。** `glidePose` の弦バグを最初のテストは捕まえられなかった。両端の方位が同じ「スクロールで抜ける」経路で書いていたためで、方位も回る「HOME ボタン」の経路にして初めて落ちた
- **実装の式を言い換えた assert を書かない。仕様をそのまま書く。** 変異テストは「テストと実装の食い違い」は捕まえるが、**「テストと実装が揃って仕様から外れている」ことは原理的に捕まえられない。** セクション寄りの姿勢は `camera.up` が world +Y のままで**看板が鏡文字**になっていたのに、テストは `angleAt(10) ≈ π/2 - SECTION_TILT` と**実装の式をそのまま写して**緑だった。しかも `it("looks down at the subject rather than up at it")` は赤道上の建物で `forward` がちょうど world +Y になるため**縮退しているからこそ通っていた**。姿勢の類は「`camera.up` と視線が30°以上離れている」のように、**壊れたときに何が起きるかを直接書く**（`cameraLayout.test.ts` の `describe("sectionUp")` が実例。詳細は [docs/review.md](review.md) A-1/A-2）
- **定数の docstring が間違っていると、レビューする側が定数を信じて実装を疑う。** `SECTION_TILT` は「その建物のローカル地平線からの仰角」なのに「法線から傾ける角度」と書いてあり、そのせいで「cos/sin が入れ替わっている」という**誤診が1回まるごと生まれた**（入れ替えると仰角70.5°の真上見下ろしになり、参考写真から遠ざかる）。値ではなく説明のほうを直すべき場面がある
- **「配信物に実在するか」だけは `public/` を読んで確かめる。** `data/projectModel.test.ts` の6件（実績の画像がある／同じサイトを指す `demoUrl` のページがある／その `demoUrl` に末尾スラッシュが無い／過去バージョンの HTML の `src=`・`href=` が自分のディレクトリの内側／HTML・RSC ペイロード・JS・CSS に出てくる画像のパスが自分のディレクトリの内側で、しかも実在する／過去バージョンのすべての `.html` に `noindex` があり、ペイロードの robots・googlebot も `noindex`）は純粋ロジックではなく `node:fs` でファイルを読むが、DOM もレンダラも要らないので node 環境のまま回る。**どれもビルドは通って画面で黙って壊れる種類**——画像は `unoptimized` なので書き出しは参照先を見ずに `public/` を丸写しし、`basePath` を忘れた過去バージョンは HTML だけ描いて現行サイトの `/_next/...` を取りに行き、`next/image` の文字列 `src` には `basePath` がそもそも効かず、`noindex` は外れても見た目が何も変わらない。変異8種（画像名の誤記・存在しない版・`demoUrl` の末尾スラッシュ・`index.html` の無いディレクトリ・HTML の1チャンクだけ `/_next/` に戻す・`/archive/v10/` を指す・チャンク内の画像パス1つだけ前置を外す・アーカイブ内の画像を消す）と、`noindex` まわりの変異4種（v0 に足した `<meta>` を消す・v1 の `.txt` ペイロードを `index, follow` に戻す・HTML に埋め込まれたエスケープ済みペイロードの googlebot を戻す・404 ページの robots を全部消す）で全部落ちることを確認した
- **HTML だけを検査しても「アーカイブの外を指していない」とは言えない。** 最初の版のテストは `index.html` の `src=`／`href=` だけを見ていて緑だったが、v1 の制作実績の画像は**クライアントでしか描かれない**ので HTML に出てこず、実際には現行サイトの `/images/` を借りていた。検査の範囲は「訪問者の画面に出るもの」ではなく「**ビルドが URL として名指しできるもの全部**」（HTML・RSC ペイロード・JS・CSS）で決める
- **無言で失敗する機構は、機能したことを別途テストする。** near ズームでリーダーラインとスポットライトマーカーが完全に死んでいたのに（マーカーの投影 y がビューポート外に落ちて可視判定が恒常 false）、`hide()` は設計どおり静かに何もしないので誰も気づかなかった。**距離・オフセット・構図を触る変更は、それが殺しうる「見えるはずのもの」を名指しで検算する**（`scene/camera/markerScreen.ts` の `markerOnScreen()` のように純関数へ切り出し、実測した最悪ケースを fixture でテストする）
- **読み物のページの本文は `src/content/` を読んで検査する**（`content/contentFiles.testutil.ts`。`public/` と同じく node 環境のまま `node:fs` で読む）。制作実績とノートについて、(1) 登録と MDX が両方向に過不足なく対応する、(2) 本文が `MIN_PROSE_CHARS`（2,000字）以上ある、(3) MDX に `#` の見出しが無い、(4) 本文中のサイト内リンクが実在するページを指す（`content/links.test.ts`）。**どれも壊れてもビルドは通るか、画面では気づけない**——登録の無い MDX は黙って配信されず、下書きは黙って公開され、slug の打ち間違いは押されるまで 404 にならない。あわせて、読み物のページの canonical が自分自身を指すこと（`reading/pageMeta.test.ts`）、サイトマップに全ページが載ること（`app/sitemap.test.ts`）、`ads.txt` の発行者 ID が広告スクリプトと一致すること（`data/site.test.ts`）も押さえた。変異14種で確かめた（canonical を消す・`siteName` を消す・古い順に並べる・同じ日の並びを逆にする・ありえない日付・存在しない制作実績・リンクの slug の打ち間違い・登録の無い MDX・本文に `#` の見出し・サイトマップからノートを落とす・`ads.txt` の番号違い ほか）
- **ナビ（`hub/nav.test.ts`）は、リンクが実際に置かれる場所を基準に URL を解決する。** 「読み物のページから `/#about` でハブのそのエリアへ行く」を `new URL(href, "https://miiiwa.com")` で確かめると、`/` の抜けた相対の `#about` もパスが `/` になって通ってしまう。基準を読み物のページの URL（`/notes/...`）にした。変異10種で確かめた（ノートを経歴の後ろへ・自分のページを無視・`/notes-archive` を `/notes` の中と見なす・ハッシュから `/` を落とす・常に先頭を光らせる・お問い合わせを消す・一覧だけ光らせる・`leadsToHub` の3種）。2026-09-20 にナビをエリア（`NAV`）とページ（`PAGE_LINKS`）の2本に分けたとき、ページ側の変異8種でも確かめた（ノートを外す・行き先の打ち間違い・末尾スラッシュ・`/notes-archive` を中と見なす・完全一致だけ・常に先頭を光らせる・ページもハブ扱い・キーの衝突）。**ページの行き先は、文字列ではなくサイトマップと突き合わせる**——`/note` や `/notes/` の打ち間違いはビルドも型も通り、押されるまで 404 にならない
- **実行環境の時間帯で結果が変わるテストは、変異を見逃す。** `formatNoteDate` を `new Date(date)` で書き直す変異が、日本時間（UTC+9）では緑のまま生き残った——UTC の0時はその日の9時なので、日付がずれるのは UTC より西だけ。テストの中で `process.env.TZ = "America/Los_Angeles"` にしてから呼び、戻すようにして赤になった。**時間帯を跨ぐ不具合のテストは、壊れる側の時間帯を自分で選んで走らせる**
- **「今日」のデータで日付を比べるテストは、「ビルドした日」と区別できない。** サイトマップの `lastModified` をノートの日付ではなくビルド日時にする変異が、日単位の比較（`toISOString().slice(0, 10)`）をすり抜けた——ノートが全部今日の日付だったため。ミリ秒まで比べる（日付だけから作った `Date` は時刻が 00:00:00Z）形にして赤になった。2026-09-20 にノートの日付を実装日へ振り直したとき、**先頭の1件だけを見ていたこのテストを全件に広げた**——全ノートに最新のノートの日付を付ける変異は、先頭の1件（最新のノート）だけを見るテストを素通りする
- **検査の対象を正規表現で拾うテストは、正規表現そのものも検査する。** 本文中のリンクを拾う式が何にも当たらなくなると、リンクの検査は1件も見ずに全部緑になる。`links.test.ts` に「拾うべきものを拾い、外部 URL は拾わない」を1件置いた
- **2つの射影を互いに比べるテストは、共有している部品が揃って間違っていても通る。** HTML を3Dに置く CSS の計算が WebGL の射影と一致することを確かめるテスト（`cssView.test.ts`）は、カメラの基底（`cameraBasis`）の上向きの符号を反転しても緑のままだった——両方が同じ基底を使うから。「注視点の少し上はカメラ空間で上、右は右」を独立に書いたテストを足して落ちるようになった（2026-10-01、手順4）
- **テストが比べる相手が、アプリが実際に使う関数かを確かめる。** スマホのカードレールのテスト「両隣のカードは、スワイプでカメラに頼む行き先と一致する」は、惑星の巡回の関数（`adjacentOnTour`）と比べていた。アプリは手順2で部屋の関数（`adjacentSection`）に替わっていたので、レールの両隣が部屋の順と食い違ったまま緑だった。比べる相手を部屋の関数にし、「自己紹介の両隣はお問い合わせと制作実績」を書き下したテストを足した（2026-10-01、手順9）
- **既定値から試すテストは、既定値へ戻す変異を見逃す。** 照明の「ほかのスイッチに触れない」を全部点灯の初期値から試していて、切り替えのたびに灯りを初期値へ戻す変異が通った。消灯した状態から試すように直した（2026-10-01、手順6）
