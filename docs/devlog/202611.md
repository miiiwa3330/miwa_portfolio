### 座ったときの視線を、PC の画面がヘッダーに被らない高さへ上げる

**ユーザー「もう少し上を向いて下さい。ヘッダーとPCの画面が被らない程度に」。PC の席の見下ろし（`seatedPitch`）を「画面の上端と手の中間」から「画面の上端を 16:9 の枠の上から12%に置く」へ変えた。13.9° → 10.8°（3.1° 上）。**

- **なぜ枠の割合で決めたか**: 被るかどうかはヘッダーの高さ（px）と窓の高さで決まる。ヘッダーの部品は窓の上から84px で終わる（外枠の `p-9` の36px＋ナビの `h-12` の48px。ユーザーのスクショの実測 84px と一致）。スクショの窓（CSS で 1710×948）では8.9%。12% にすると、その窓で画面の上端は上から約108px、ヘッダーとのあいだに約24px 空く。窓の高さを 800px まで縮めても 84px は10.5%で、12% の内側に収まる
- **見下ろしを窓ごとに計算する案は採らなかった**: 座った姿勢は `zoomView("desk")` の1つの値で、机の視点の切り替え・飛行・体の姿勢・首の可動域の判定がどれもそこから読む。窓の大きさを入れると、それらが全部窓に依存する。基準の 16:9 で1つの角度に決め、窓の比が違えば上端の位置が少しずれるのは許した（16:9 と 1.80 の差は 0.5% ほど）
- **捨てたもの: 手が枠に入ること**。手の置き場（`HAND_Y`）は枠の下端より約1.7°下へ出る（16:9 の縦の半画角 20.4° に対して −22.1°）。手の上側だけが覗く。ヘッダーを避けるにはどの角度でも手の置き場は枠から出る（もとの式で手は下端の1.4°内側しかなかった）ので、ヘッダーを避けられる最小に近い角度にした。画面の下端は枠の上から72%で、画面全体は入っている
- **下を向いて目が前へ出る（`headLean`）は効かないまま**: 15°より浅いので、席の目の位置は変わらない
- **Mac の席は変えていない**（`macSeatedPitch` は「くぼみの上端と手の中間」のまま）。今回の指摘は PC の画面
- テスト: 「画面の上端と手がどちらも枠に入る」を外し、「画面の上端が枠の上から12%（ヘッダーの 84/948 より下）、画面の下端が枠の中」と「中間より2°以上上を向く」（もとの式に戻すと落ちる）を足した。`npm test` 816件通過、`npx tsc --noEmit`・eslint エラーなし
- ヘッドレスでの撮影はしていない（座る飛行の着地待ちが長い。[verification.md](../verification.md)）。実機のブラウザで確認してもらう

### 席に留める: 開いた瞬間から座っていて、立とうとすると限界エンジニアの一言

**ユーザー「現状、デスク周り以外の仕様が未実装なので、立ち上がれないようにしたい。サイトが開かれた瞬間にデスクに座った状態。立ちあがろうとすると『もう少し頑張ろう』とか『この作業までやろう』みたいな限界エンジニアの一言を表示」。一言は22個を出して見せ、「全てランダムで」と決まった。**

- **スイッチを1つにした**（`state/seatLock.ts` の `SEAT_LOCKED`）。デスクの外ができたら戻すので、消して書き直すのではなく、false にすれば今までの部屋に戻る形にした
- **止めるのは `AppStateContext` の1か所**: 立つ道を数えると、タスクバーの「席を立つ」（`unfocus`）・「戻る」（`goHome`）・稲妻のマーカー（`setActiveSection`）・ホログラムの読了（`unfocus`）・ブラウザの戻る（URL の effect）。ボタンごとに止める案は、1つ止め忘れれば立ててしまうので採らなかった。3つの関数の中で断り、`standRefusals` を1つ増やす。キーで歩く（`freeWalk`）は寄っているあいだもともと動かないので、手を入れていない
- **ロゴは断らず、首を PC の画面へ戻す**: ロゴは「最初に戻る」で、最初が席になったから。押すたびに一言が出ると、ロゴが壊れているように見える
- **URL に `#desk` を積まない**: 席が唯一の居場所なのに `#desk` を履歴に積むと、ブラウザの戻るが「立つ一歩」になり、押すと何も起きない。`/#desk` と `/#about` で来たら `replaceState` で消す（`pushState` だと戻る先が1つ増える）
- **開いた瞬間に座っている**: 最初の状態を `"desk"` にしただけでは、カメラが中央に立った姿勢から席まで歩いて座る飛行が開くたびに走る。`poseRef` の初期値を席の姿勢にし、`prevSectionRef` の初期値を開いたときの区画にして、行き先の effect は「前と同じ区画」なら何もしないようにした。React の開発時の effect の二度実行でも、2回目は前と同じ区画なので飛ばない。初回の判定用の ref を別に足す案は、二度実行の2回目で飛んでしまうので採らなかった
- **一言は直前と同じものを出さない**（`pickStandLine`）。ランダムのまま、2回続けて同じだと押しても何も変わらないように見えるため。直前の1つを除いた21個から引く。表示は「戻る」の上に2.8秒、押すたびに新しい一言で時間を数え直す（`StandRefusal.tsx`、`aria-live="polite"`）
- 踏んだ罠: テストの等間隔の乱数を `i / 22` にしたら、`Math.floor((3 / 22) * 22)` が2になって22個のうち21個しか出なかった（浮動小数の丸め）。刻みの中央 `(i + 0.5) / 22` にした
- テスト: `standLines.test.ts`（両言語が空でない・最初はどれでも出る・直前のものは出ず残り21個はどれも出る・乱数の両端で範囲内）。`npm test` 820件通過、`npx tsc --noEmit`・eslint エラーなし
- ヘッドレス（1710×948 と 390×844 のスマホ、ユーザーの dev サーバー :3001）で確かめた: 開いた直後から席に座っていて `location.hash` は空。「席を立つ」→「このコミットまでやろう。」、「戻る」→「このバグ、さっきまで再現してたのに。」（続けて違う一言）。ブラウザの戻るはサイトの前のページ（`about:blank`）へ出て、`#desk` の一歩は無い。`/#desk` で来るとハッシュが消え、履歴は増えない。スマホの「戻る」でも一言が出た。コンソールのエラー0件
- 踏んだ罠: ヘッドレスでは一言が DOM にあるのに写らなかった。毎秒数フレームしか出ず、0.18秒のフェードインが終わる前に2.8秒の表示時間が切れていた（不透明度0のまま消えた）。実機の不具合ではない。不透明度を CSS で強制して見た目を撮った（[verification.md](../verification.md) に追記）

### ローディング画面: 部屋の最初のフレームまで「Miiiwa. OS」の起動ログ

**ユーザー「サイトアクセス時最初の画面が描画されるまでのローディング画面を追加したい」。部屋は外部ファイルを1つも読まない（形も模様もコードで作る）ので、待つのは「スクリプトの読み込み → シーンの組み立て → 最初の描画（シェーダーのコンパイル込み）」の3つ。その3つを行にした起動ログにした。**

- **にせの進捗バーにしない**: 読み込むファイルが無いので `useProgress`（three の LoadingManager）は何も数えない。時間で進むバーは実際の進みと関係が無い。3つの段階はどれも本物の合図で取れる。hydration は `BootScreen` の effect、組み立ては `<Canvas>` の `onCreated`（R3F 9.6.1 のソースで、シーンの部品が commit されたあと・最初の描画の前に呼ばれることを確かめた）、最初の描画は `useFrame` の優先度2（描く `LensRenderer` の優先度1の後ろ）
- **見た目は PC のタスクバーの「Miiiwa. OS」の起動**: 部屋の主の PC が立ち上がる体にした。systemd の `[  OK  ]` の並び。済んだ行は緑の OK、進行中の行にはオレンジ（ロゴの点と同じ色）の点滅カーソル、まだの行は薄く
- **段階は `Hub` の state に載せない**（`state/bootChannel.ts`、`facingChannel` と同じ購読の形）。`Hub` を描き直すと three.js の木がまるごと再調停されるので、組み立て中に3回それをやると最初の描画が遅れる
- **組み立てと最初の描画はメインスレッドを止める**: 文字を JS で入れ替えるスピナーは、肝心のあいだ止まって見える。カーソルの点滅は CSS の不透明度のアニメーション（合成スレッド）にした
- **1回のページ読み込みにつき1回**: 読み物のページから戻るときも canvas は作り直すが、そのたびに起動ログを流すと「戻る」が重く見える。要望も「サイトアクセス時」
- **WebGL が作れないときに起動ログのまま止まらないか**: three が例外を投げ、R3F の `<Canvas>` がそれを上へ投げ直すので、エラーの画面になる。待ち続けることはない。保険のタイムアウトは足していない（遅い端末で、描く前に消えてしまうため）
- 計測（ヘッドレス、SwiftShader、dev サーバー、1710×948）: 静的 HTML の時点で起動ログが出ている。スクリプトの読み込みは0.6秒、組み立ては6.7秒、最初の描画は48.5秒で済み、0.5秒で消えた。最初の描画が遅いのはソフトウェアのラスタライズだから。実機の GPU では未計測。ページのエラー0件
- `npm run build` が通り、`out/index.html` に起動ログの文がある。`npm test` 823件通過、`npx tsc --noEmit`・eslint エラーなし
- テスト: `bootChannel.test.ts`（段階ごとの各行の状態・段階は戻らない）

### ローディング画面を軽くし、「Miiiwa.」と `----- n%` → `[OK]` の形へ

**ユーザー「ローディング画面は大前提、すごく軽いことが最も重要。なかなか出てこないなんてことは絶対にないように。Miiiwa.を大きく上に、その下に --------------n% が100%になったら [OK] に変化し、サイトが開くように」。まず何が最初の描画を遅らせているかを測り、それを外してから見た目を作った。**

- **何が遅らせていたか**（遅い 4G 150ms・1.6Mbps、CPU 4倍遅く、ヘッドレス）: 圧縮なしで配って測ると、今のビルドの最初の描画は3.7秒、CSS の読み終わりは3.6秒。同じ HTML から JS の script を抜くと、最初の描画は1.7秒・CSS は1.6秒。**描画を止める CSS（125KB、gzip で21KB）が、同時に始まる JS（2.2MB、gzip で約600KB）と回線を取り合っていた。** script はどれも `async` で、HTML の解析は止めていない。描画を隠すスタイル（`hide-fouc` など）も無かった
- **gzip で配って測り直すと**、今のビルドは1.05秒（CSS は0.86秒）。`inlineCss` で CSS を HTML に埋め込むと0.57秒、ローディング画面を `<body>` の先頭へ移して0.52秒（2回目以降の4回で0.516〜0.532秒）
- **`inlineCss` の代わりに払うもの**: HTML が gzip で 15KB → 79KB。CSS が `<style>` と RSC の payload の2か所に入る（同梱ドキュメントの「Styles are duplicated」）。ただしローディング画面より手前に来るのは `<head>` の `<style>` の22.5KB だけ。CSS はページごとに読み直し（キャッシュされない）、全ページにかかる。読み物のページ（`/products`・`/notes`）の見た目は変わらないことを撮って確かめた。採ったのは、要望が「絶対に」すぐ出ることだから
- **却下: CSS をローディング画面の分だけ別にする**。外部の CSS は `<head>` にある限りすべての描画を止めるので、ローディング画面の style を直に書いても先には出ない。Next はその `<link>` を差し替えさせない
- **却下: 3段（スクリプト・組み立て・描画）だけで % を出す**。いちばん長いのは遅い回線での JS の到着なのに、そのあいだ0%のまま動かない。React が動く前から数えるため、1.5KB の script を HTML に埋め込んだ。ページの JS のファイル（14〜15本）の到着と3段を同じ重さで数える。重みを付けないのは、読み手の端末でどれに何秒かかるかを測るものが無いから。最大のファイル（1.15MB）が届くあいだは % が止まるが、それは本当に待っているところ
- **script は1つの関数として書き、そのソースを `<script>` に入れる**（`bootScript.toString()`）。テストと本物が同じコードになる。本番では SWC が縮めるが、外の名前を使わないので縮めたあとも動く（1,458バイト）。テストは埋め込む文字列そのものを `new Function` で偽の DOM に対して動かす
- **踏んだ罠: dev のスマホで0%のまま消えた。** React が hydration のあとで画面の中身（`dangerouslySetInnerHTML`）を元に戻していた（0.58秒、script が95%まで描いたあと。`MutationObserver` で見つけた）。script はつかんだままの古い部品に書き続けていた。最初は「描くたびに探し直す」だけにしたが、戻されたのが最後の合図のあとだったので直らなかった。画面の直下の子を `MutationObserver` で見張り、差し替わったら描き直すようにして直った。本番のビルドでは戻されなかったが、頼らない
- **読み物のページから入ったとき**: そのページには埋め込みの script が無いので、リンクで部屋へ来ると `BootScreen` の effect が同じ `bootScript` を呼ぶ。`/products` から来て `[OK]` まで進んで消え、そのあと読み物のページへ行って戻ったときは出ないことを確かめた
- 見た目: 「Miiiwa.」は Geist の900、`clamp(56px, 13vw, 128px)`。点線24個とその右に % を等幅で置き、% の幅は4文字ぶん取って、桁が増えても点線が動かないようにした
- 計測の罠を [verification.md](../verification.md) に足した（ブラウザ起動直後の1枚目は何を開いても約3.5秒遅い・Python の `http.server` は圧縮しない・ポート8765は別の作業のサーバーが使っていた）
- `npm test` 828件通過、`npx tsc --noEmit`・eslint エラーなし、`npm run build` が通る
