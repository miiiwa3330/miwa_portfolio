### 手を、指のある手に作り直した

- **寸法は身長からの比**（`room/hand.ts`）。シートの手はポケットの中で測れない。手の長さは身長の0.108倍（18.1cm）、幅は0.048倍（8.1cm）、手のひらは長さの57%。指の長さは中指を1として、人差し指0.91・薬指0.95・小指0.75
- **腕の先の点を「手のひらの下面が載る点」と読み、手首をそこから8cm 手前に置いた。** 腕の骨（肘〜腕の先0.34m）とキーボード・マウスの上の手の点（`DESK_HANDS`、0.82m）はそのままにした
  - 最初は手首を4.5cm 手前（前の楕円の中心＝腕の先）に置いた。手が楕円（10cm）より長いので、指がキーボードの奥の段とマウスの前端を2〜3cm 越えた。8cm にすると、目に見える前腕（肘〜手首）は0.26m で、人体計測の0.155倍とちょうど合う
  - 手のひらの中心を腕の先に置くと、手のひらがマウスの背に7mm めり込んだ（腕の先は0.82m、マウスの一番高い所は0.827m）。手のひらの厚みの半分だけ上げた
  - **退けた案: 右手の点（`DESK_HANDS`）を2cm 手前へ下げる。** 握りは自然になるが、座ったときの視線（`seatedPitch`）が −13.91° から −14.37° に動き、「マウスは手の下にある」テストも書き換えになる。手首の位置で解けたので、レイアウトは触っていない
- **握りは4つ。値は探索して決めた**（すべて仮）。指先がキーやマウスの面の0〜3mm 上に来て、どの関節もめり込まない曲げを、手首の反りごとに指1本ずつ探した。目安の行（ホームポジション）に近いほど点を良くした
  - **タイピング**（左手）: 手首の反り0.25rad。指先はキートップの1〜8mm 上、中指と薬指はホームポジションの段（z 0.068〜0.076）。手首をまっすぐにしたままでは、手のひらがキーの高さにあるので、指を曲げると奥の段に2〜3cm 沈んだ
  - **EX-G**（右手、かぶせ持ち）: 反り0.1rad。人差し指・中指・薬指はボタンの前寄りの1〜2mm 上。EX-G は S サイズ（幅6.4cm）で手は男性の大きさなので、小指は右の外、親指は左の外に出る。それ以上曲げると側面に入った
  - **M0100**（Mac の席の右手）: EX-G の握りのままでは、まっすぐ伸ばしても薬指と小指が入った（M0100 は低く箱形）。反り0.2rad にして、人差し指と中指は前端の上に浮かせた
  - **ぶら下げ**（立っているとき）: 軽く開いた手
  - **退けた案: 指の曲げに上限を置かない。** 探索がホームポジションに寄せようとして、中指が合計3.16rad（181°）曲がる鉤爪になった。1本2.3rad を上限にした。マウスを「つかみ持ち」（第2関節を強く曲げる）で探す案も、右手が拳のようになったので退けた
- **机の上の手は水平に寝かせる**（握りの `level`）。Mac の席では肘が0.73m と低く、前腕がマウスへ上り坂になるので、前腕に沿わせると指がマウスの3〜8cm 上に浮いた。寝かせると PC の右手が16〜19mm 浮いたので（PC では右の前腕が下り坂）、寝かせた状態で探し直した
- **手の甲の向き**: 腕が水平に近いほど上、垂れるほど外。最初は「上」と「少し外」をいつも混ぜていて、垂らした腕（少し前に下がる）では手の甲が外から48°前を向いた
- **描画は手1つにつき `SkinnedMesh` 1つ**（`Self.tsx` の `Hand`）。手のひら（角の丸い箱を、手首から指の付け根へ細め、甲を膨らませた形）と骨ごとのカプセル（16本）を1つにまとめ、各頂点を1本の骨に重み1で載せた。片手1回の描画のまま、握りを滑らかに混ぜられる。退けた案は2つ: (1) 指の骨ごとのメッシュ（片手16回の描画。人物は本体とホログラムの2体で、鏡・監視カメラ・魚眼の立方体でも描かれる）(2) 3つの握りを静的なジオメトリで持って切り替える（座る途中で指が一瞬で変わる）

### Opus 5.5 × Blender の作り方を、ユーザーが共有した4件の投稿から調べた

- **ユーザーの指示**: X の投稿4件を参考に、Opus 5.5 × Blender の使い方を学ぶ。x.com はログインが要るので、公開の埋め込み用 API（`api.fxtwitter.com`）で本文・スレッドの返信・引用記事を読み、動画は数枚の静止画にして質を見た
- **深夜のコインランドリー**（hayashimon1、Claude Code × Blender MCP、Blender を手で触らずプロンプトだけ）: (1) 完成イメージの2D画像を先に作って渡す (2) 空間→モデル→質感の順に、箱のブロックアウトから細部へ段階を分ける（ドラムの穴はブーリアン、洗濯物は布シミュレーション）(3) 質感はすべてプロシージャル。塗装剥げ・隙間の汚れ・上面の埃・床際の汚れ・垂れ跡・指紋を1つのノードグループにして、全材質に強さを変えて重ねる (4) 看板やステッカーは「印刷物」として作る（Blender 内で2Dを組み、真上から描いてテクスチャにし、退色・黄ばみ・艶・剥がれを重ねる。3D文字はCGっぽくなる）(5) ダメ出しで詰める（「不自然」「余白が多い」「もっと参考画像に」→ Claude がクローズアップで1つずつ確かめて直す）。人の仕事は良し悪しの判断と指示
- **AI だけで作る部屋**（Yokohara_h）: 物ごとに「直接モデリング」か「画像生成→3D生成→Blender で修正」かを AI に判断させた。照明・コンポジット・カメラワークはほぼダメ出し無しで良くなった
- **teardown**（elvar、three.js。Blender ではない）: 参考画像がすべてを決める（無しで頼んだ3体は「よくあるおもちゃ」になった）。参考と並べた静止画を撮って3回直してから先へ進む。批評家として確かめる（めり込み・浮いた部品を静止画で探し、カメラで隠さず数字で直す）
- **SHELTER**（hayashimon1）: three.js 製のブラウザの短編ゲームで、ニットを着たロボットが動く。ブラウザでもこの水準の人物は出せる
- **この部屋に当てはめると**: 外部の3D生成は使わない（ユーザーの決定）ので、直接モデリングだけ。参考はシート（`reference/4/3.png`）の前・横・後ろの立ち姿で、毎回同じ向きから描いてシートと並べる。**投稿の作品はどれも Cycles で描いた映像で、Web に持ち込む工程が無い。** この部屋では (1) プロシージャルの材質は glTF に書き出せないので、テクスチャへ焼く (2) Blender の照明は持ち込めないので、焼くのは AO まで (3) 骨の長さはコードの定数（`figure.ts`・`self.ts`・`hand.ts`）に合わせ、テストで押さえる、が要る
- **前に私が出した見立てを改める**: 「私がスクリプトで作るだけでは、今より滑らかになる程度」と書いたが、投稿の作品は Blender を手で触らずに作られていて、質が高い。ただし、どれも家具・機械・部屋（硬い物）で、**顔や髪や服のような柔らかい物を AI だけで作った例は、この4件には無い**。服のしわは布シミュレーションで作れる見込みがある
- **SHELTER の人型は three.js のコードで組んだものではなかった**（ユーザーの問いを受けて、公開されているゲームの中身を確かめた）。キャラクターは `echo-motion.glb`（4.4MB）で、書き出しは Blender（`Khronos glTF Blender I/O v5.2.39`）、メッシュの名前が `tripo_mesh_…`（Tripo の画像→3D）、テクスチャは色・法線・ORM の3枚、約1.8万三角形、骨41本と Blender で付けたクリップ（歩く・見回す・座る・つなぎ）。部屋は照明を焼き込んだ Blender の GLB（26.6MB、光の計算をしない材質、約28万三角形）。three.js は読み込んで再生するだけ。上で「ブラウザでもこの水準の人物は出せる」と書いたのは、作り方を確かめる前の見立てだった。**あの質は画像→3D生成と Blender の組み合わせで出ている**ので、外部サービスを使わない決定のもとでは、そのまま手本にはならない。規模の目安（1体約1.8万三角形・テクスチャ3枚・骨41本）としては使える

### 頭と髪だけを Blender で試作し、表現を調べた

- **ユーザーの指示**: 外部サービスを使わない方針のまま、頭と髪だけで試作して、Blender の表現を調べる。Blender 5.1.2（Apple M5、Metal）をヘッドレスで、Python のスクリプトだけで動かした（Blender の MCP は使っていない）。スクリプトと画像はスクラッチパッドにあり、リポジトリには入れていない
- **進め方は、共有された投稿の型どおり**: シートの前・横・後ろ・表情「通常」と同じ向きで描き、シートの切り出しと並べた1枚を毎回作って、自分でダメ出しして直す。1回の作り直し（4方向の描画を含む）は約45秒。初回だけ Metal のカーネルのコンパイルで115秒かかり、キャッシュが効いたあとは小さな絵で約1秒だった
- **寸法はシートの画素から測った**（1px＝4.72mm、168cm／356px）。目と目の間は ±47mm、眼鏡は全幅171mm・レンズ71×50mm、眉は目の36mm 上、口は61mm 下・幅41mm、耳は目の高さから口の高さで左右 ±134mm、首の幅70mm、横から見た耳は目の127mm 後ろ。顎・頭頂・髪の幅は `figure.ts` と同じ値を手で写した（**本番にするなら、コードから書き出した数を読む**。今は2か所にある）。肌の色は表情の絵の頬で RGB 約(165,122,98)
- **頭**: 頭蓋・頬・顎の楕円体を滑らかにつないだ形（符号付き距離）に、四角い面の球の頂点を吸着させた。鼻・眼窩・眉の盛り上がりはガウスの凹凸。目は球にした虹彩の色の帯と、垂れ目に傾けた上まぶたの殻、まぶたの線・眉・口は太さのある線、眼鏡はレンズの縁・ブリッジ・つるの線
- **髪は3回、作り方を変えた**:
  1. **細い束を並べるだけ**（1回目）: 針のような束の隙間から頭皮が見えた。束は塊にならない
  2. **塊の殻＋表面の束**（2〜5回目）: 頭皮から浮かせた殻の厚みを、シートの髪の外形から逆算した（頭頂39mm、横52mm、後ろ54mm、前髪の上24mm）。赤道より下は真下へ垂らし、生え際は前が額の上（分け目の側は高く）、横が耳の上、後ろが顎の高さ。殻の頂点を消して作った縁はぎざぎざになったので、生え際の線へ寄せて頭皮へ巻き込む縁にした。後頭部の下に肌の帯が出たので、耳の後ろと襟足は頭皮に沿った髪の膜で首まで覆った（耳の前まで覆うとフードに見えた）。束は約150本、縁に外へ跳ねる房を22本足した（40本では毛先がヤマアラシのように尖った）。**外形はシートに近づいたが、束が平たい花びらや羽根に見える**
  3. **ヘアカーブ（1本ずつの毛）**（試し）: 同じ束の経路の中に毛を生やし、髪用のシェーダー（Principled Hair BSDF、メラニン0.98）で描いた。約6,000本では疎らで茶色く透け、約2.5万本（約39万点）で束の部分は筆で描いたような毛の質感になった。ただし束の間に下の塊がつるりと見えてまだらになる。頭皮全体を毛で覆う（グルーミング）まで行かないと活きない。描画は4方向で約1分
- **色**: 最初は髪が銀色に見えた。白い背景がそのまま環境の光として映り込んでいたため、背景はカメラに映る分だけ明るくし、照らす光としては4分の1にした（Light Path の Is Camera Ray で分ける）。AgX の色変換では肌が白っぽいピンクになったので Standard にした
- **重さ**（5回目、殻＋束の方式）: 細分化の前で約10.4万三角形（束4.2万・殻3.8万・頭1.6万）、細分化後は約40万。SHELTER のキャラクター1体（約1.8万）や私の予算案（全身3万以下）より桁が大きい。Web に持ち込むなら、殻を荒くし、束の本数と分割を減らす必要がある
- **分かったこと**: (1) 外形・比率・分け目・耳・眼鏡のような「形」は、スクリプトと並べ比べの往復で詰められる (2) **髪の質感**（束の中の毛の流れ）は、面の束では出ない。出すなら、ヘアカーブで頭皮全体を覆った高精細の髪を作り、それを束の面に法線・AO・色として焼き付ける（ゲームの「ヘアカード」と同じ手順）。ヘアカーブはそのままでは Web に持ち込めない (3) **顔の魅力**（大きな黒目・まぶたの厚み・鼻・頬の赤み・前髪の影）はほとんど出ていない。シートとの差は髪より顔のほうが大きい
- **次の候補**: (a) ヘアカーブで頭皮全体を覆う → 束の面へ焼き付ける → GLB に書き出して `/lab` と部屋の光で見る（Web までの一本道を通す）(b) 顔の作り込み（目・まぶた・鼻・頬）
