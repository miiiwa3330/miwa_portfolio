## 前提: ツールの役割分担

- **Blockbench**: オブジェクトのモデリング（オフラインの資産制作ツール）
- **Three.js / R3F**: ブラウザ上でその資産をリアルタイムに描画・操作・アニメーションさせる実行エンジン

「Blenderが本体でThree.jsが補助」ではなく、**Blockbenchは素材出し、Three.js/R3Fが体験そのものを作る側**という位置づけ。実装の工夫（カメラ演出、インタラクション、パフォーマンス制御）はほぼ全てR3F側に集中する。

このプロジェクトではClaude Code経由でBlockbenchデスクトップアプリ（MCPプラグイン、`localhost:3001/bb-mcp`）を直接操作し、モデルを作成・GLB出力している。

## Q1. キューブのサイズと部屋・小物のスケール差問題

**疑問**: 全てのキューブをXYZ=1,1,1（Blockbench内の固定1ユニット）で作ると、本のような小物は10×10ブロックで済むのに、部屋のような大型オブジェクトは実寸に比例させると500×500ブロックが必要になり、手作業（MCP経由のキューブ配置）では非現実的だった。

**解決策**: ネイティブのブロック数を実寸に比例させるのをやめる。
- どのオブジェクトも**ネイティブ解像度は10〜80ブロック程度**に収まるよう作る（部屋であっても500×500ではなく40〜80角程度に抑える）
- 実寸への到達は、R3F側で読み込む際の**`scale`/`voxelSize`倍率**に全て任せる
- これはMinecraftのブロック/アイテムモデルと同じ考え方——実寸に関係なく固定の小さな内部グリッド（例: 16×16×16）で全アセットを作り、実際のサイズは配置時の変換（transform）で決める

**なぜこれでいい**: シーン全体の「ボクセルの見た目の統一感」は、生の座標一致（1ブロック=1ワールドユニット）で担保するのではなく、**カテゴリごとに倍率のルールを決めて一貫させる**（例: 小物系はscale 1、建築系はscale 10、など）ことで担保すればよい。

## Q2. 別々に作ったパーツを、どうやって1つの複合施設にまとめるか

**疑問**: 壁・屋根・家具などパーツごとに作成したオブジェクトを、最終的にどう合体させるのか。

**解決策**: パーツの性質によって2パターンを使い分ける。

### ① 動かない・単体で完結したパーツ → Blockbench内で1つのプロジェクトにまとめる
1. Blockbenchの**「グループ」機能**を使い、同じ1つのプロジェクト内に壁・屋根・家具などを別グループとして保持する
2. Blockbench画面上でグループごとの相対位置・相対サイズを視覚的に調整する（**パーツ間の比率合わせはこの段階で確定させる**——結合後にR3F側でパーツ単体の比率を直すことはできない）
3. まとめて1つのGLBとしてエクスポート
4. R3F側では、複合施設**全体**に対して1つのスケール倍率をかけてシーンの実寸に合わせるだけでよい

### ② 使い回す・独立して動かすパーツ → 別ファイル + R3F側で実行時に組み合わせる
人・乗り物・写真のように複数箇所で使い回すもの、または他の施設とも共有するものは、別のBlockbenchプロジェクト（別ファイル）として作り、`useGLTF`で個別に読み込んでR3F側の`<group>`で配置する。

**判断基準は「動くかどうか」ではなく「単体で完結しているか、複数箇所で使い回す部品か」。**
観覧車の「土台」と「回転するホイール」は動きが違う（片方は固定、片方は回転）が、どちらも観覧車という1つのオブジェクトでしか使わないので、**同じ1つのファイルの中で別グループとして持てば十分**（詳細はQ4）。

## Q3. BlockbenchのUI操作: タブとグループの違い

**疑問**: 「1プロジェクトで複数パーツを保持する」というのは「グループを追加」の話か？画面上の「＋」ボタンで新規タブを作るのは、別プロジェクトになるのか？

**解決**:
- **「＋」で新規タブ = 完全に別ファイル（別プロジェクト）**。それぞれ独立したシーン・アウトライナー・Undo履歴を持つ。パーツの結合には使わない。
- **「グループを追加」= 同一プロジェクト内のフォルダ分け**。壁・屋根・ドアなどを同じ1つのファイルの中で論理的に整理する仕組みで、これがそのまま1つのGLBとして書き出される。複数パーツを1ファイルに保持したいときはこちら。
- 既に別ファイルとして保存済みのパーツを後から持ってきたい場合は、新規タブを開くのではなく、今開いているプロジェクトのまま **File > Import** で別の`.bbmodel`を読み込む。読み込んだ内容は新しいグループとして今のプロジェクトに追加される。

**結論**: 基本の作業スタイルは「タブは1つ開いたまま触らず、グループの追加（＋必要ならImport）だけで組み立てていく」。

## Q4. 回転・アニメーションのピボット（回転軸）はどう合わせるか

**疑問**: 観覧車の土台と回転部分のように、動く部分の回転中心をどう正しい位置に配置しているか。

**解決**: Three.jsでは**回転は常にオブジェクト自身のローカル原点(0,0,0)を中心に起きる**。これを踏まえて2つのテクニックがある（既存コード [`Decorations.tsx`](https://github.com/miiiwa1121/miwa_portfolio/blob/v1-voxel-planet/src/scene/objects/Decorations.tsx) に両方の実例あり）。

### ① ジオメトリ自体を回転軸中心に作る（観覧車の`wheel`）
リムの座標を`cos(rad)*R, sin(rad)*R`のように最初から原点(0,0)を中心とした円として計算し、ハブも原点をまたぐように配置する。ジオメトリ自体が最初から「原点＝回転中心」になっているので、そのラッパー`<group>`をそのまま回すだけでよい。

### ② ジオメトリの原点がズレている場合、補正オフセットを挟む（`VoxelBus`のバス車体）
角(0,0,0)基準で作った車体のように、原点が中心とズレているモデルは、動かす外側の`<group>`と実際のジオメトリの間にもう一段`<group position={[-x,-y,-z]}>`を挟んで、車両の中心が外側グループの原点に来るよう補正する。

**Blockbench制作への応用**: 実務的には②（補正オフセット方式）の方が楽。Blockbench側では作りやすい位置（角基準など）でモデリングし、回転軸にしたい座標だけ控えておいて、R3F側でその値をマイナスにして補正オフセットとして使う。

## Q5. 動く部分は本当に「別ファイル」が必要か（訂正ポイント）

**疑問**: 観覧車の土台は固定、ホイールは回転する——動きが違うパーツは別プロジェクトにすべきか？

**解決（Q2の判断基準の再確認）**: 不要。**必要なのは「動かす部分が独立した名前付きグループ/ノードとして書き出されていること」であって「別ファイルであること」ではない。**

glTF/GLBは1ファイルの中に複数の名前付きグループを持てる。R3F側の`useGLTF`は`nodes`としてファイル内の全要素を個別に参照できる形で返すので、以下のように**1つのファイルのまま**でも部分的なアニメーションが可能:

```tsx
const { nodes } = useGLTF("/models/glb/ferris_wheel.glb");
const wheelRef = useRef<THREE.Group>(null);

useFrame((_, delta) => {
  if (wheelRef.current) wheelRef.current.rotation.z += delta * 0.25;
});

return (
  <group position={position}>
    <primitive object={nodes.support} />
    <group ref={wheelRef} position={[0, centerY, 0]}>
      <primitive object={nodes.wheel} />
    </group>
  </group>
);
```

別ファイルが本当に必要なのは、**複数箇所・複数の施設で使い回すオブジェクト**（人・乗り物・壁に飾る写真など）の場合のみ。

## Q6. 具体例: 壁に飾る写真オブジェクトの配置と浮遊アニメーション

**疑問**: 複合施設内の特定の壁に写真オブジェクトを飾り、少し浮遊させたい場合、「この部屋のこの壁のこの位置」という指定は可能か？

**解決**: 可能。写真は複数の部屋・壁で使い回す部品なので別ファイル（別プロジェクト）にし、既存の`Trees`/`StreetLamps`と同じ「1モデル定義→複数箇所に配置」パターンに従う。

位置指定は2通り:
- **建物の階層をそのまま`<group>`のネストで表現**（部屋の位置 → 壁の位置・向き → 壁面から少し浮かせた写真の位置、と入れ子にする）
- **ワールド座標を直接指定**（`Trees`/`StreetLamps`と同じ、単純な配置ならこちらで十分）

浮遊アニメーションは`Clouds`/`Villagers`（[Decorations.tsx](https://github.com/miiiwa1121/miwa_portfolio/blob/v1-voxel-planet/src/scene/objects/Decorations.tsx)）と同じ「refの配列＋インスタンスごとのphase/seed」パターンで、各写真が同じタイミングで動かないようにする。
